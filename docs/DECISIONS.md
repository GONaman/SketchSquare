# Decisions log

One line of reasoning per decision. Items marked **needs owner confirmation** are business gaps from Part 3 of `AGENTS.md`.

| # | Decision | Reasoning |
|---|----------|-----------|
| D1 | Work happens via small feature branches merged by squash PR; `main` is never pushed to directly. | Owner requirement. |
| D2 | Old Firebase-based prototype (local, uncommitted) is not carried over; the spec mandates our own NestJS backend. | Spec Part 1 stack is fixed. |
| D3 | Generated Dart code (`*.g.dart`, `*.freezed.dart`) is committed. | Keeps `flutter analyze`/`test` reproducible without a codegen step in CI. |
| D4 | MinIO runs from `bitnamilegacy/minio` in docker-compose. | `minio/minio` and `minio/mc` Docker Hub images were not pullable on the dev network; Bitnami's image bundles the `mc` client too. |
| D5 | Flutter uses Riverpod 2.6 (`flutter_riverpod`/`riverpod_annotation`/`riverpod_generator` ^2.6) rather than 3.x. | `riverpod_generator` 3.x/4.x require Dart ≥3.8; the pinned SDK is Dart 3.7. |
| D6 | Flutter fonts: Inter via `google_fonts` runtime download (falls back to the platform font offline); tests turn it off via `AppTheme.useGoogleFonts = false`. | Avoids committing font binaries now; bundle Inter as an asset in Phase 7 (release readiness) if offline-first typography matters. |
| D7 | Auth session in Flutter is a stub (`authControllerProvider` returns an approved architect `User`) until Phase 2. Sign-in / verification-pending routes are placeholder screens so the redirect guard has targets. | Lets the shell render and the guard be unit-tested now. |
| D8 | `razorpay_flutter` is in `pubspec.yaml` (builds for web and passes analyze/test) but unused until Phase 5. | Spec stack; no conflicts found. |
| B1 | Backend pins Prisma 6, `@nestjs/config` 4 and `@nestjs/swagger` 11. | Newer majors need Nest 12 / ESM-only builds that Jest (CJS) can't load; Prisma 7 requires driver adapters. |
| B2 | Env is validated by a zod schema with local-dev defaults (infra values, dev JWT secrets) that are disabled when `NODE_ENV=production`. | App/tests/`npm run openapi` run with zero config locally, while prod must set every secret explicitly. |
| B3 | `GET /health` returns `{status, checks:{db,redis,s3}}` with values `"up"`/`"down"`; HTTP 503 and `status:"error"` if any check is down. | Contract fixes the shape but not the values; 503 lets orchestrators detect failure. |
| B4 | `npm run openapi` builds first and runs the compiled generator. | The Swagger CLI plugin (DTO schema inference) only runs under `nest build`. |
| B5 | Prisma default naming (PascalCase tables, camelCase columns), `uuid` ids via `gen_random_uuid()`; raw SQL must quote identifiers. | Avoids `@map` noise everywhere; documented in `docs/data-model.md`. |
| B6 | Added `FreeDownload (userId, drawingId)`, `RefreshToken`, `PasswordResetToken`, `ProcessedWebhookEvent`, `AuditLog`, `Facing` enum, `DrawingStatus.UNDER_REVIEW/FAILED`, `Drawing.failureReason`, `User.architectRatingCount`, `Purchase.paidAt`, `Withdrawal.bankAccountId/failureReason/updatedAt`, `DrawingSheet.fileName/sizeBytes/sha256`. | Needed by the free-quota, auth rotation, idempotency, moderation and contract requirements; spec's domain model lacked them. |
| B7 | `plotAreaSqft` is kept by a `BEFORE INSERT/UPDATE` trigger; `searchVector` is a generated stored tsvector (title A, description B) with a GIN index. | Impossible to forget in app code; Prisma sees `searchVector` as `Unsupported` with `@default(dbgenerated())` to avoid migration drift. |
| B8 | Ledger: append-only (triggers block UPDATE/DELETE) and every `txnId` must sum to 0, enforced by a deferred constraint trigger plus `LedgerService.postTransaction` pre-validation. Corrections are reversing transactions. | Money safety backstop independent of application bugs. |
| B9 | e2e tests run `prisma migrate deploy` in Jest `globalSetup` and clear data with `TRUNCATE` (`resetDb`). `TEST_DATABASE_URL` overrides the DB so parallel worktrees can use separate databases (auto-created). | Ledger rows can't be DELETEd; keeps test DB in sync with migrations. |
| U1 | The Flutter upload form collects `bedrooms` and `tags`, but the app only sends them when built with `--dart-define=UPLOAD_SEND_EXTENDED_METADATA=true`; the contract documents them as optional additions. | The backend validates with `forbidNonWhitelisted`, so sending unknown fields before the drawings module supports them would 400 every draft. **Backend follow-up:** accept/persist `bedrooms`, `tags`, then flip the default. |
| U2 | There is no separate "unpublish": the seller's "Remove" calls `DELETE /drawings/:id` (status REMOVED, past buyers keep access). | The contract has no unpublish endpoint; REMOVED is the only way to take a drawing off the market. |
| U3 | Upload drafts are resume-safe via the server draft (`DRAFT` drawing + registered sheets) plus a local snapshot (`shared_preferences`: active draft id + form JSON). Files that were picked but not yet uploaded are not restored after an app restart. | Picked file handles are not durable across launches on mobile/web; uploaded sheets are, so little work is lost. |
| U4 | Client-side form limits (title 5–100, description 20–2000, plot 5–2000 ft, floors 1–20, bedrooms 0–20, ≤8 tags, price ₹1–₹10,00,000) and the 10% fee estimate are UI guard rails only; the backend stays authoritative. | The contract defines no field limits; the fee comes from `PLATFORM_FEE_BPS` server-side. |
